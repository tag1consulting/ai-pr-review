# v2.19.0

## Added

- **`AI_SUPPRESS_WALKTHROUGH` (action input `suppress-walkthrough`) leaves the Walkthrough section out of the summary comment.** The default is `false`, so nothing changes unless you set it. The Summary text, Type and Effort stay. Bitbucket cannot collapse the per-file table the way GitHub and GitLab do, so this is the way to shorten the comment there. The section is removed after the model writes it, so the summarizer cost does not change. On Bitbucket, a summary comment that already has a table loses it on the next run. On GitHub and GitLab, an existing comment keeps its walkthrough until the summarizer next runs. Images older than 2.19.0 ignore the setting. A caller that passes `suppress-walkthrough` to the `slash-commands.yml` reusable workflow needs a ref that includes the input.

## Changed

- **Boolean environment flags ignore surrounding whitespace.** A value such as `" true"` now counts as true for every flag read through the shared parser. Only `true`, `1` and `yes` are true, as before.
- **Release PRs get a full-mode review on every push, and work lands on a release branch first.** The `release/*` route in this repository's own `policy.yml` now uses the `deep` (full) policy instead of `quick`. Feature and issue PRs target a long-lived `release/vX.Y.Z` branch, so the release PR into `main` carries the whole code diff since the last release. This changes how this repository is developed and has no effect on the action for other users.

See [CHANGELOG.md](https://github.com/tag1consulting/ai-pr-review/blob/main/CHANGELOG.md) for full technical detail.
