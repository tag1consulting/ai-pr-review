# v2.6.0

## What's new

**Four new static analyzers check documentation instead of code, and none of them can trigger `REQUEST_CHANGES` on their own:**

- `docs-api-check` — flags a doc comment (docstring, PHPDoc, JSDoc, godoc, etc.) whose documented parameters, return type, or exceptions no longer match the function's actual signature.
- `docs-missing-check` — flags a newly-added public API (function, class, exported symbol) with no doc comment at all. Diff-gated: only new code is checked, not pre-existing undocumented code.
- `docs-ref-check` — catches broken Markdown links and heading anchors introduced or touched by the current PR.
- `docs-drift-check` — catches a doc that still references a file the current PR deletes or renames.

All four are token-free (no LLM call) and run as part of the existing static-analyzer pass. See [Static Analyzers → Documentation checks](../static-analyzers#documentation-checks) for configuration, and the design rationale in `docs/adr/0001-tree-sitter-not-node-for-doc-mismatch.md` and `docs/adr/0002-hand-rolled-doc-ref-checker-not-lychee.md` in the repo.

## Fixed

- **`golangci-lint` analyzer produced zero findings on every Go PR.** It invoked `--out-format=json`, a flag removed in golangci-lint v2 — the version this image has pinned since the v2.0.0 bash-to-Python rewrite. Switched to `--output.json.path=<file>`, the v2 equivalent.
- **`phpcs` analyzer silently dropped all findings** whenever a file's violations were entirely non-fixable, or a mix of fixable and non-fixable. phpcs 4.x redesigned exit codes as a bitmask (0=clean, 1=fixable, 2=non-fixable, 3=both), and the analyzer's exit-code guard still assumed the pre-4.0 scheme where 2 meant a fatal/config error.
- **`phpcs`'s PSR12 fallback path** (used when the Drupal coding standard isn't installed) now also checks docblock/signature mismatch via `Squiz.Commenting.FunctionComment`, matching the coverage Drupal repos already get via `Drupal.Commenting.FunctionComment`.
- **CI's lint job now installs the `[context]` extra**, so `mypy --strict` and the test suite actually exercise tree-sitter code paths (context enrichment, `docs-api-check`) instead of silently skipping them. That exposed a real `mypy --strict` gap: `tree_sitter_language_pack`'s `get_parser()` has returned different `Parser` implementations across releases — some accept only `bytes`, others only `str`. The parse call now tries `bytes` first, matching the currently-resolved package version, with a `str` fallback for older/alternate versions.
