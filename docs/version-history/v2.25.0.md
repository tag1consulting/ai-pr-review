# v2.25.0

## Upgrade warnings

Read these before you update. Each one can change what a run does.

- **`AI_FORK_POLICY` defaults to `block`.** A fork pull request is not reviewed and gets one pause comment. This closes a gap: v2.24.1 had no fork gate, so a fork PR on `pull_request_target` ran with the repository secrets. To review forks, set `AI_FORK_POLICY=auto` (a contained run with spend caps) or `label`. Read [Fork pull requests](../fork-prs) first.
- **Under `auto` and `label`, a trusted author or an approved fork pull request has a cost ceiling.** The ceiling is `AI_FORK_MAX_COST_USD` (default 2 USD) when `AI_MAX_COST_USD` is 0. v2.24.1 had no ceiling. A non-zero `AI_MAX_COST_USD` sets a different limit for those runs.
- **Under `auto`, the engine creates a bot-managed issue titled "ai-pr-review fork spend (do not close)".** It lists pull request numbers and run costs. The workflow needs `issues: write`, and the repository must have Issues enabled. Without them, every non-trusted fork run pauses with a ledger error.
- **An agent that returns output the engine cannot read now counts as a failed agent, on every run.** Before, unreadable output counted as no findings, so a pull request could get APPROVE. Now the run posts COMMENT and names the agent. With `AI_FAIL_ON_FINDINGS=true` the run also exits with code 2.
- **A custom GitHub bot identity must set `GITHUB_BOT_USERNAME`.** The engine now reads the SHA watermark and the skip comments only from comments that the bot wrote. Without the variable, the engine ignores its own summary and skip comments from any other login.
- **The checkout step must set `persist-credentials: false` for a fork review.** The engine pauses a fork run when `.git/config` holds a persisted credential. A default `actions/checkout` stores one.
- **Proxy and certificate variables reach analyzers, but a proxy value with credentials does not.** A proxy value that has an `@` is dropped. A fork run passes no proxy variable at all. Every analyzer and git subprocess now gets a scrubbed environment on every run, so an analyzer that needs another variable must get it through `AI_ANALYZER_ENV_PASSTHROUGH`.
- **The `@mention` and `owner/repo#N` neutralizing applies to fork runs only.** A run for a pull request from the same repository is not changed.
- **A rescan reads the fork settings from repository variables.** The `slash-commands.yml` workflow forwards all six fork settings from the repository variables of the calling repository: `AI_FORK_POLICY`, `AI_FORK_TRUSTED_ASSOCIATIONS`, `AI_FORK_MAX_COST_USD`, `AI_FORK_DAILY_MAX_COST_USD`, `AI_FORK_DAILY_RESERVED_SHARE` and `AI_FAIL_ON_FORK_GATE`. A repository that sets one of them to a non-default value must also set it as a repository variable.
- **The `statuses: read` permission is needed only under `AI_FORK_POLICY=label`.** The example `fork-approval.yml` is for that policy only.

- **Checkov now works, so a pull request that changes infrastructure files gets checkov findings.** Before, checkov exited with an error on every run and reported nothing (#1102). Expect new findings and some new noise. Add `checkov` to `exclude-analyzers` to switch it off.
- **GitLab and Bitbucket read the summary and skip notes only from the bot (#1104).** On GitLab, set `GITLAB_BOT_USERNAME` when the token cannot call `GET /user`, for example `CI_JOB_TOKEN`. Without it, every run does a full review and posts a new summary note.

## Added

- **Fork pull requests can be reviewed with limits (opt in with `AI_FORK_POLICY=auto`).** The default is `block`, so a fork pull request is not reviewed. Under `auto`, a non-trusted author gets the fork profile.
  - Every analyzer and git subprocess gets a scrubbed environment.
  - Only analyzers with a trusted or isolated configuration run. eslint, golangci-lint, semgrep, shellcheck, hadolint and kube-linter are skipped.
  - The prompts carry no PR body, commit message, open-issue title or branch name.
  - The review event is COMMENT. Suggestions are off. A fixed banner starts each comment. The text has no external link or image.
  - Spend is capped per run (2 USD), per pull request (4 runs and 6 USD), per author (2 open pull requests) and per day (50 USD). A pull request that reaches a cap pauses. A maintainer resumes it with `/ai-pr-review rescan`.
  - `OWNER` and `COLLABORATOR` authors are trusted and get the normal pipeline.
  - A live end-to-end test of fork reviews must pass before the default can change from `block`. GitLab and Bitbucket are not gated (#1104).
  - New settings: `AI_FORK_POLICY`, `AI_FORK_TRUSTED_ASSOCIATIONS`, `AI_FORK_MAX_COST_USD`, `AI_FORK_DAILY_MAX_COST_USD`, `AI_FORK_DAILY_RESERVED_SHARE` and `AI_FAIL_ON_FORK_GATE`.
  - The gate covers GitHub only. The review still runs in the job that holds the secrets. Issue #1098 tracks the split into two jobs. See [Fork pull requests](../fork-prs) and `SECURITY.md` for the limits that remain.
- **`AI_ANALYZER_ENV_PASSTHROUGH` names extra environment variables for analyzers.** A secret-looking name is refused with a warning. See [Configuration](../configuration).
- **A review says when a finding that the review resolved earlier is back (#1089).** The new comment says that a similar finding here was resolved earlier and is back. The match needs the same file, a line within 3 lines, a compatible category and the same source, against a thread whose code changed. Nothing is reopened or suppressed. GitHub only. See [Features](../features).
- **Telemetry schema 4 records what each finding agent returned (#1088).** `agent_yield` has one entry for each agent that answered. Consumers that switch on `telemetry_schema_version` must accept `"4"`. See [Configuration](../configuration#telemetry-hooks).
- **A push-level recall corpus for the review agents (#1088).** It holds real review findings, labeled by hand. It is a measurement tool and changes no review behavior.

## Changed

- **Behavior change: the engine scrubs secrets from every posted string.** It also caps a string at 262,144 bytes, strips invisible characters from untrusted prompt text, escapes a closing tag that could end an untrusted block, and neutralizes a log line that starts with `::`. This applies to every run.
- **A fork run reads the local suppression rules from the base branch.** On every run, a suppression rule with an invalid regular expression is dropped alone and the other rules stay.
- **The telemetry `outcome` can be `skipped_fork_gate_failed`.** The configuration page now lists it, and `skipped_context_window_failed` too.
- **The container action passes the fork settings, `AI_ANALYZER_ENV_PASSTHROUGH` and `GITHUB_EVENT_NAME` to the container.** The `slash-commands.yml` workflow checks out with `persist-credentials: false`.
- **The README, the docs index and the examples README link to the fork documentation.** `examples/workflows/fork-approval.yml` is new.
- **The image has ruff 0.17.2, tflint 0.65.0 and trufflehog 3.99.4.**

## Security

- **phpstan no longer runs PHP from the analyzed repo.** Phpstan ran `vendor/autoload.php` from its current directory even with a trusted configuration. It now starts in an empty scratch directory with an allowlist environment, and the files go in by absolute path. Phpstan no longer resolves the project's own classes, so it may report fewer findings.
- **The checkov analyzer reads no config from the analyzed repo (#739, #1102).** Checkov merges `.checkov.yaml` from the current directory and from `HOME` with an explicit config file. Checkov now starts in an empty scratch directory with an empty `HOME`.
- **GitLab and Bitbucket: a forged summary or skip marker no longer hides commits from review (#1104).**

## Fixed

- **The checkov analyzer now scans (#1102).** Before, checkov rejected the comment-only config file and exited with an error on every run.

## Internal

- **A bounded, read-only tool loop and sandbox for review agents exist in the code, and nothing calls them (#1088).** They change no review behavior and have no setting.
