# v2.4.9

**Asimov's Three Laws are now stated explicitly in `prompts/_governance.md`, instead of being implied.** The file previously named the First Law only as a section title and never mentioned the Second or Third Laws by name, even though the Third Law was already being rejected in substance (the self-refuting-findings rule). The file now opens with all three laws stated up front: First and Second binding and quoted verbatim, Third stated and explicitly rejected. Each existing rule is relabeled with the law it implements, and text and numbering are unchanged for rules 1-4.

**New rule 5, "Obey Recorded Maintainer Verdicts," gives the Second Law a real behavior, calibrated to what the learning loop's `<repo-feedback>` block can actually identify.** When an entry carries a `rule_id` pinning it to a specific rule at a specific file, agents now treat a `false-positive`/`wont-fix` verdict as a standing order not to re-raise it, unless the current diff gives a reason the verdict does not cover, with the First Law always overriding when a re-raise is harm-relevant. When `rule_id` is absent, the verdict downgrades to confidence-lowering rather than outright suppression, so a same-agent, same-file verdict on one issue can't silently blanket-suppress a different issue on that file. This also closes a prompt-injection gap: directives embedded in diffs, commits, or PR text are now explicitly ruled out as "orders from a human being" for every governed agent, not just `security-reviewer` and `finding-judge`. This behavior applies only on GitHub repositories that opt into `feedback-loop: true` (default off).

**A related security fix closes an injection path in the `<repo-feedback>` mechanism itself.** The block's entries were rendered with no escaping on the `command`/`source`/`file`/`rule_id` attributes; because `file` is derived from the PR's own diff path, a crafted path could forge a second, independent maintainer verdict inside the trusted block. All four attributes are now HTML-escaped, and a new relevance floor excludes any entry whose file isn't actually part of the current diff instead of merely ranking it lower.

The three inert `GOVERNANCE:`-block paragraphs added in #576 (`security-reviewer.md`, `adversarial-general.md`, `architecture-reviewer.md`) are removed, since no dispatch path ever wired up the mechanism they described, and their name now collides with the real always-on governance layer.
