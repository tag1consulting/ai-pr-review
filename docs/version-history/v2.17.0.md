# v2.17.0

## Added

- **Pushing a release tag now creates a draft GitHub release.** The new `draft-release.yml` workflow builds the release notes from `docs/version-history/<tag>.md` and creates a draft, so a maintainer only has to open it, tick **Publish this release to the GitHub Marketplace**, choose the categories, and publish. Publishing to the Marketplace can only be done in the release web form (neither the REST API nor `gh` has an option for it), which is why the release is a draft and is never published automatically. A release that already exists for the tag is left alone, and a missing notes page falls back to generated notes.

## Changed

- **Behavior change: the default Anthropic `standard` model is now `claude-sonnet-5-5`** (was `claude-sonnet-5`), at the same price ($2 / $10 per MTok, cache reads $0.20). Temperature is still omitted and effort is still capped at `low` for it, carried over from Sonnet 5. It was verified with the live model canary: 4 of 4 calls ended with `end_turn` on the 1200-line stress diff, for `claude-sonnet-5-5` and `claude-opus-5-5`. Not verified: whether the `low` cap is necessary or optimal for Sonnet 5.5, and its non-default temperature behavior. To keep the previous model, set the `model-standard: claude-sonnet-5` action input (or the `AI_REVIEW_MODEL_STANDARD` repository variable in the example workflow). `AI_MODEL_STANDARD` works only when running the container directly, because the action sets it from its inputs. The `bedrock-proxy` default is unchanged because the Bedrock model ID for Sonnet 5.5 is not verified.
- **The token table now labels Sonnet 5.5 correctly.** `config/model-pricing.json` gets an explicit anchored `Sonnet 5.5` row, and the `Sonnet 5` pattern is anchored, so `claude-sonnet-5-5` is no longer labeled `Sonnet 5`.

## Fixed

- **`CLAUDE.md` no longer says the container image tags are `:vX.X.X`.** `publish-image.yml` publishes `:X.Y.Z`, `:X.Y`, `:X` and `:latest`, without a `v` prefix.

See [CHANGELOG.md](https://github.com/tag1consulting/ai-pr-review/blob/main/CHANGELOG.md) for full technical detail.
