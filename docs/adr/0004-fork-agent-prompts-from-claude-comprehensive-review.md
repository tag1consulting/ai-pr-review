# Fork agent prompts from claude-comprehensive-review; keep language profiles shared

This engine's seven review-agent prompts (`prompts/code-reviewer.md` and siblings) were built by importing content from the `claude-comprehensive-review` Claude Code plugin, most recently through issue #372 and its child issues (#396-#400), which backported "agent prompt improvements" wholesale. `claude-comprehensive-review`'s agents are Claude Code subagents: each has real tool access (Read, Bash, Grep, an MCP GitHub tool), and an orchestrating skill parses their free-form prose output. This engine's agents are one tool-less HTTP call per run; the only contract the pipeline understands is a fenced `json-findings` block matched by a regex (`findings/extract.py`).

Importing prompt *instructions* across that boundary has already caused a production incident and a still-live defect. Issue #446 (closed 2026-06-05): `issue-linker.md` instructed the model to run `gh issue view` and `git diff`; the model, given no tools, emitted literal `<tool_call>` XML into a posted PR comment. The fix cleaned that one prompt. Five prompts still carry the same class of instruction today (Read-tool guidance, `git diff --name-only` fallbacks, `EXTENDED_THINKING` triggers that nothing in this engine ever sets). Separately, #372's backport standardized five prompts on emitting the bare word `NONE` for a clean run, following `claude-comprehensive-review`'s convention where an orchestrator reads that token from prose. `findings/extract.py` has no handling for it at all: an agent that obeys `NONE` fails the fence match, logs a "no json-findings block" warning, and its entire review is silently discarded. The two prompts #372 did not touch still carry the opposite instruction ("do not output NONE"), so the prompt set now contradicts itself along exactly the line of which files that one issue edited.

We are forking: this engine's agent prompts are owned here, not synced from the plugin, and future prompt improvements in `claude-comprehensive-review` are not backported. A prompt instructs the model about a runtime it does not have unless someone deliberately re-checks every import against this engine's actual tool-less, regex-parsed contract, and that check has already failed once in production and once by omission.

Language profiles (`language-profiles/*.md`, 19 files, byte-identical between the two repos as of this writing) are the one surface that stays shared. A profile is content describing what goes wrong in a given language; it makes no claim about tool access or output format, so it is portable across the two runtimes in a way an agent prompt is not. The `parity-audit` skill is narrowed to compare only this surface; its agent-prompt comparison arm is retired, and its analyzer-comparison arm (`claude-comprehensive-review` has no analyzer code, only docs) is dropped as producing no signal.

A pytest prompt lint (`tests/python/test_prompt_lint.py` or similar) now scans `prompts/*.md` for tool-affordance markers (`Read tool`, `git diff`, `gh issue`, `mcp__`, `EXTENDED_THINKING`) and for the bare `NONE` empty-state instruction, failing the build if either reappears. This is the enforcement mechanism for the fork: the failure mode is not "someone imports a whole prompt again," it is "someone borrows one instruction from a plugin prompt while fixing something else," and only an automated check catches that at the point of the edit rather than at the point a PR gets malformed output.

**Considered and rejected:** keep syncing prompts with a review caution added to the parity-audit skill's output. Rejected because the class of defect has already evaded review twice — once into production (#446), once into a merged PR (#372, which introduced the contradiction while fixing an earlier one) — and a caution in a skill description does not change what a reviewer's attention is drawn to during a routine backport.

**Considered and rejected:** retire the `parity-audit` skill entirely rather than narrow it. Rejected because the language-profile surface is genuinely shared and currently in sync; retiring the whole skill would stop watching for profile drift with no replacement, trading a known-good signal for a known-bad one.
